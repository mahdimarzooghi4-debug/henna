# Catalog 002 — درگاه وب خواندن کاتالوگ خریدار

**دامنه:** اتصال API واقعی کاتالوگ به سمت سرور Next.js بدون وانمود کردن به ساخت فریم خریدی که هنوز طرح مصوب آن در Figma متصل موجود نیست.

## خروجی اجرایی

- مسیرهای same-origin مخصوص مصرف‌کننده در وب: `GET /api/catalog/categories`، `GET /api/catalog/products?page=&pageSize=&categoryId=&search=` و `GET /api/catalog/products/{id}`. هر سه روی سرور Next.js به `/api/v1/catalog/...` در ASP.NET وصل می‌شوند.
- مقصد از `HANA_API_BASE_URL` موجود خوانده می‌شود. در production فقط مقصد HTTPS پذیرفته می‌شود؛ مسیرها ثابت هستند و category/product ID و جست‌وجو پیش از ساخت URL اعتبارسنجی می‌شوند. redirect بالادست رد می‌شود و timeout برابر ۸ ثانیه است.
- هیچ Cookie یا Bearer از مرورگر به API عمومی کاتالوگ ارسال نمی‌شود؛ برای خواندن کاتالوگ، نشست خریدار لازم نیست. پاسخ‌های سرور هیچ‌گاه دادهٔ نامعتبر، status داخلی، price، sellerId یا هر فیلد اضافهٔ upstream را مستقیماً به مرورگر منتقل نمی‌کنند. تنها id/name/slug گروه و id/categoryId/name/kind/description کالا/خدمت مجازند.
- `400` پارامتر صفحه‌بندی/UUID/جست‌وجوی نامعتبر؛ `404` محصول منتشرشدهٔ ناموجود؛ `503` قطعی، JSON نامعتبر، پاسخ غیرمنتظره یا پیکربندی ناموجود؛ `200` تنها برای پاسخ واقعی و کاملاً معتبر. **عدم دسترسی سرور هرگز با فهرست خالی اشتباه نمی‌شود.** پاسخ‌ها `Cache-Control: no-store` دارند.
- اعتبارسنجی فهرست: شماره صفحهٔ ۱ تا ۱۰۰۰۰، اندازهٔ ۱ تا ۵۰، جست‌وجوی حداکثر ۸۰ نویسه، UUID معتبر؛ کلیدهای اضافی یا تکراری رد می‌شوند.

## تست

- تست وب در CI با HTTPS upstream آزمایشی، پاسخ موفق دسته/فهرست/جزئیات، نشت‌نکردن bearer/cookie و price و metadata اضافه، 400/404/503، و no-store را بررسی می‌کند. mock صرفاً داخل فایل تست است؛ دیتای ساختگی/قیمت نمونه داخل UI یا shipping API وارد نشده است.
- smoke build وب در نبود `HANA_API_BASE_URL` برای مسیرهای معتبر کاتالوگ 503 و برای ورودی نامعتبر 400 را آزمایش می‌کند.
- مرحلهٔ پیشین Catalog 001 همچنان API واقعی و PostgreSQL، انتشار/عدم انتشار دسته و محصول را آزمون می‌کند؛ این مرحله اتصال وب را پوشش می‌دهد، نه ساخت فروشگاه یا فروش.

## مرزهای باز

این مرحله **هیچ صفحهٔ خانه/فهرست/جزئیات جدید از فیگما** و هیچ قیمت/موجودی/عرضهٔ فروشنده/سبد خرید اضافه نمی‌کند. فایل Figma متصل هنگام بازبینی همین مرحله فقط فریم‌های login وب/اپ و ثبت‌نام فروشگاه وب را داشت. برای طراحی buyer UI باید فریم مصوب آن اضافه شود. قرارداد کاتالوگ فعلی هویت محتوایی را حمل می‌کند؛ عرضهٔ قابل‌خرید باید بر پایه فروشندهٔ تأییدشده و شهر/محدوده و موجودی مستقل ساخته شود. SMS واقعی همچنان پیش‌نیاز ورود عملیاتی است.
