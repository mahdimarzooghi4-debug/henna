# Frontend 019 — URL پایدار مرور عمومی کالا و برگشت با زمینهٔ فهرست

## انگیزه و تأیید

Frontend 015/018 خانه، فیلتر و جزئیات مصوب را در Next.js ساخته بودند، اما مرور چند صفحه و بازگشت از جزئیات در وب جست‌وجو، دسته‌بندی و شماره صفحه را از دست می‌داد؛ Refresh نیز صفحهٔ اول را دوباره باز می‌کرد. این مرحله **بدون صفحه/جریان بصری جدید**، رفتار ناوبری همان چهار فریم خانه و شش فریم جزئیاتِ قبلاً صریحاً تأییدشده را تکمیل می‌کند.

## قرارداد URL واقعی وب

- URL صفحهٔ اصلی می‌تواند `/?categoryId=<published UUID>&search=<term>&page=<N>` باشد. `page` از ۱ تا ۱۰۰۰۰، `search` حداکثر ۸۰ نویسه و `categoryId` UUID غیرصفر است. شمارهٔ ۱، جست‌وجوی خالی و «همهٔ دسته‌ها» از query حذف می‌شوند. `pageSize=20` ثابت در درخواست داخلی است، نه URL قابل‌اشتراک.
- بارگذاری مستقیم URL، HTML اولیه و نخستین درخواست عمومی را با همان query معتبر آغاز می‌کند؛ نه نمایش اشتباه صفحهٔ اول. تغییر فیلتر/جست‌وجو page را ۱ می‌کند. انتخاب دسته فقط با ID موجود در پاسخ واقعی public categories انجام می‌شود.
- `window.history.pushState` برای تغییر فیلتر/جست‌وجو/صفحه و `popstate` برای Back/Forward استفاده می‌شود. `replaceState` آدرس‌های کثیف/نامعتبر را به URL متعارف allowlist تبدیل می‌کند. نتایج قبلی تا پاسخ query تازه به‌عنوان نتیجهٔ تازه نمایش داده نمی‌شوند؛ AbortController موجود حمل‌ونقل قبلی را متوقف می‌کند.
- کارت `/products/{id}` فقط همین سه پارامتر عمومیِ allowlisted را با خود می‌برد؛ هدر و دکمهٔ بازگشت جزئیات از آن‌ها `/?...` می‌سازند. **`returnTo` پذیرفته نمی‌شود** و مقصد خارجی، کوکی، bearer، شمارهٔ تلفن یا queryهای ناشناخته منتقل نمی‌شوند. امکان کپی لینک مستقیم فهرست یا جزئیات از نوار آدرس وجود دارد؛ نه دکمه/طرحِ اضافهٔ تأییدنشده.
- URL با دستهٔ UUID ناشناخته هرگز دستهٔ ساختگی به UI اضافه نمی‌کند؛ API عمومی دربارهٔ وجود محصول منتشرشده در آن دسته تصمیم می‌گیرد. هنگام خطای دسته‌بندی، ۵۰۳ همچنان خطاست نه کاتالوگ خالی؛ رفتار اصیل Frontend 015 باقی است.

## تست CI و مرزها

`tests/web-buyer-navigation-smoke.mjs` parser/serializer واقعی همان کد shipping را با URL فارسی، مرز page، UUID نامعتبر، دادهٔ اضافی/تکراری و حذف open redirect آزمایش می‌کند. `tests/web-buyer-navigation-browser-smoke.mjs` علیه **Next production و Chromium واقعی** از دادهٔ منتشرشدهٔ حافظه‌ای **فقط CI** استفاده می‌کند: لینک مستقیم فیلترشده به صفحهٔ ۲، نخستین درخواست، رفتن به جزئیات و هر دو لینک بازگشت، Refresh، Back/Forward، انتخاب دسته و بازنشانی صفحه، URL نامعتبر و viewport 390px. هیچ کاتالوگ ساختگی shipping، قیمت یا فروشگاه/سفارش جدید ایجاد نشده است.

**مرز:** این مرحله دربارهٔ URL مرور **وب** است. اپ Expo فعلاً فیلتر/جست‌وجو/صفحه را در حافظه هنگام برگشت از جزئیات حفظ می‌کند؛ deep link خارج از اپ و Android/iOS link association، هنوز طراحی/پیاده‌سازی و تست native ندارند. قیمت، موجودی، سبد، لجستیک و پرداخت همچنان جدا هستند.
