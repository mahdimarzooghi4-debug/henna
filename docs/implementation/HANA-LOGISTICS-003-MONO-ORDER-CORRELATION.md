# HANA-LOGISTICS-003 — نگاشت پایدار سفارش حنا و شناسه‌های مونو

**مرحله:** Technical implementation  
**وضعیت:** مخزن هم‌بستگی و گذارهای اولیه پیاده‌سازی شده؛ dispatcher سفارش به API مونو هنوز وجود ندارد.

## دادهٔ پایدار

جدول `commerce.mono_delivery_correlations` برای هر سفارش ارسال فقط یک ردیف دارد و این مقادیر را نگه می‌دارد:

- شناسهٔ سفارش حنا؛
- کلید idempotency ثابت مشتق‌شده از شناسهٔ سفارش؛
- وضعیت محلی `PREPARED`, `REQUEST_RECEIVED` یا `MISSION_LINKED`؛
- `delivery_request_id` و `mission_id` مونو، پس از دریافت پاسخ معتبر؛
- اثرانگشت SHA-256 بدنهٔ دقیق درخواست مونو، به‌صورت hex کوچک؛
- زمان‌ها و revision برای تشخیص تغییر.

آدرس، نام و شماره تماس، اقلام بسته، Quote، متن درخواست و payload رویدادهای بیرونی در این جدول ذخیره نمی‌شوند. اثرانگشت فقط برای تشخیص یکسان‌بودن بدنهٔ retry است و امکان بازیابی بدنهٔ اصلی را نمی‌دهد. شناسه‌های مونو روی هر دو ستون یکتا هستند تا یک درخواست یا مأموریت به دو سفارش حنا وصل نشود.

## رفتار retry

`PrepareAsync` فقط سفارش موجود با `FulfillmentMode=DELIVERY` را می‌پذیرد و کلید ثابت `henna-delivery-{order-guid}` را برمی‌گرداند. پیش از POST، dispatcher باید `RecordRequestIntentAsync` را با بدنهٔ نهایی فراخوانی کند. حنا اثرانگشت SHA-256 را ثبت می‌کند؛ در retry همان بدنه پذیرفته می‌شود و بدنهٔ متفاوت با همان کلید خطای `REQUEST_PAYLOAD_CONFLICT` می‌گیرد. این مانع استفادهٔ تصادفی از کلید ثابت برای دو درخواست متفاوت می‌شود.

اگر پاسخ POST مونو به‌علت timeout نامعلوم بماند، dispatcher آینده باید همان کلید و دقیقاً همان بدنه را دوباره بفرستد. برای این منظور باید snapshot سفارش و جزئیات درخواست را با همان نسخهٔ داده بازسازی کند؛ اثرانگشت بدنه را نگه نمی‌دارد. پذیرش intent پیش از ثبت پاسخ مونو الزامی است و گذار به `REQUEST_RECEIVED` بدون آن با `REQUEST_INTENT_NOT_RECORDED` رد می‌شود.

گذار به `REQUEST_RECEIVED` فقط پس از پاسخ مونو با `status=RECEIVED` مجاز است. این وضعیت پذیرش یا ایجاد مأموریت نیست. شناسهٔ مأموریت فقط پس از مشاهدهٔ آن در پاسخ خواندنی مونو به `MISSION_LINKED` نگاشت می‌شود؛ وضعیت مأموریت به وضعیت تجاری سفارش حنا تبدیل نمی‌شود.

## محدوده و آزمون

- این بخش هیچ درخواست شبکه‌ای ارسال نمی‌کند و checkout فعلی حنا همچنان فقط `PICKUP` است.
- تست PostgreSQL مهاجرت، کلید ثابت، ثبت و تکرار intent، تعارض بدنه، اتصال شناسه‌ها، جلوگیری از اتصال یک شناسه به چند سفارش و رد سفارش حضوری را می‌سنجد.
- این پیاده‌سازی به معنی آماده‌بودن sandbox، API key، بسته‌بندی، نگاشت شعبه، Quote معتبر یا webhook نیست.
