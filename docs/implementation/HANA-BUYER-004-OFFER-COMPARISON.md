# Buyer 004 — Reference Cart Offer Comparison

## Approved product behavior

Buyer 004 compares currently published Seller offers against the quantities in the signed-in buyer's reference cart. The comparison is read-only. It does not persist a seller choice and does not create a quote, order, reservation, payment, delivery promise, or logistics request.

An offer covers a cart line only when its seller-declared quantity is greater than or equal to the requested quantity. A seller's display name is not an identity key. A future order remains constrained to one seller, and the buyer must explicitly decide what to do with uncovered lines in a later order flow.

## Seller identity

Seller registration records receive a stable, opaque `public_seller_id` generated by PostgreSQL. Existing registration records are backfilled by the migration default; new rows receive an ID from the same database default. The ID is unique and independent from Identity `account_id`. Only the public ID and current store name may appear in buyer offer read models. The value is an identifier, not an authorization credential.

## API contract

`GET /api/v1/buyer/cart/offers` is account-scoped and `no-store`.

- Requires a server-resolved bearer session. Browser access is through the same-origin BFF with its HttpOnly cookie.
- Returns the cart revision, per-line current Catalog status, and groups of published offers by `seller_public_id`.
- Includes only published Catalog goods and offers belonging to submitted, approved, activated GOOD/BOTH seller applications, with positive published price and declared quantity.
- `coversRequestedQuantity` is derived server-side from the current declared quantity and cart request. It is not stock confirmation.
- Unit/precision drift since the cart line was saved is returned as `CATALOG_CHANGED`; withdrawn or unavailable Catalog goods are not represented as zero offers.
- A comparison exceeding the bounded 2,000-offer response limit fails as unavailable rather than returning a silently truncated seller list.
- All error and mutation-adjacent responses are `no-store`. No browser bearer token or seller account identifier is returned.

The per-product public offers endpoint also includes `sellerPublicId` so clients can group published offers without using display names or Identity IDs.

## Web behavior

The reference cart shows current seller groups, declared price and quantity, requested quantity coverage, and offer update time. It shows explicit unavailable states and never treats a failed read as zero offers. This page adds no seller selection action and does not change the cart.
