# Identity 005 — پایان تراکنشی OTP، حساب پایه و نشست قابل ابطال

**وضعیت:** مسیر داخلی ثبت یا بازیابی حساب اولیه و نشستِ قابل ابطال پس از OTP پذیرفته‌شده توسط provider ساخته شده است؛ در پیکربندی پیش‌فرض حنا **SMS provider وجود ندارد و API ارسال/تأیید OTP برای درخواست معتبر همچنان 503 می‌دهد**.

## پیاده‌سازی

- `OtpSignInService`: قفل advisory شماره و قفل ردیف challenge با همان ترتیب صدور OTP؛ کنترل وضعیت `ACCEPTED` و مرجع provider، تطبیق digest، بازه زمانی و سقف پنج اشتباه. سپس **در یک تراکنش PostgreSQL**: مصرف چالش، ثبت حساب پایه در صورت نداشتن حساب، به‌روزرسانی زمان تأیید شماره و ذخیره نشست. شکست ثبت هرکدام کل تراکنش را rollback می‌کند؛ شکست کد فقط شمارنده تلاش همان چالش را ثبت می‌کند.
- `SessionTokenCodec`: bearer token تصادفی ۳۲بایتی با prefix نسخه‌دار؛ پایگاه داده فقط SHA-256 مجزای دامنه از توکن را در `identity.auth_sessions` ذخیره می‌کند، نه مقدار قابل استفاده آن را.
- `AuthSessionService`: بازیابی account ID فقط تا قبل از انقضا و در نبود revocation؛ ابطال اتمیک با digest، محدودیت ۲۴ ساعت برای نشست اولیه به‌عنوان **پیش‌فرض فنی نیازمند بازبینی**. رمز عبور، refresh token، چرخش نشست و MFA ادمین در این گام ساخته نشده‌اند.
- migration سوم `20260920223000_AuthSessions`: جدول نشست، FK به حساب، ایندکس یکتای digest، ایندکس Account/expiry و قیود زمانی؛ snapshot EF و تست schema به‌روز شدند.
- `POST /api/v1/auth/otp/verify`: 400 برای داده بدشکل، 503 اگر SMS adapter واقعی، DB، کلید managed OTP یا HTTPS خارج از dev وجود ندارد، 401 برای چالش/کد ردشده و **فقط در مسیر provider واقعی** 200 با bearer token. 429 برای محدودیت نرخ IP. خروجی no-store است؛ هیچ شماره، OTP و bearer در log یا URL ارسال نمی‌شود.

## کنترل‌های دامنه

اثبات مالکیت شماره فقط **حساب پایه مصرف‌کننده** ایجاد می‌کند؛ نه فروشنده/سازمان تأیید می‌شود و نه اعتبار حمایتی، حساب قابل‌نقدشدن یا حق مدیریت اضافه می‌شود. session صرفاً شناسه حساب را resolve می‌کند و برای دسترسی حساس باید احراز نقش و مجوز جداگانه برقرار شود.

## تست و مرز انتشار

xUnit با PostgreSQL واقعی برای: ثبت حساب/نشست پس از چالش معتبر، یک‌بارمصرف بودن و رقابت دو verify، عدم ساخت حساب با کد/چالش نادرست، reuse حساب در OTP دوم، انقضا و ابطال نشست؛ تست واحد فرمت و digest bearer. گیت CI دارای تست 400/503 API و build وب/موبایل است.

**هنوز برای انتشار عمومی آماده نیست:** ارائه‌دهنده SMS و آشتی وضعیت ارسال `PENDING`، محدودسازی توزیع‌شده، تنظیم HTTPS/forwarded headers، بازبینی session transport موبایل با secure storage، پراکسی وب با HttpOnly/SameSite cookie + CSRF، refresh/revoke UX و آزمون E2E روی دستگاه لازم‌اند. درخواست موفق mock یا رمز ثابت در مخزن تولید تعریف نشده است.
