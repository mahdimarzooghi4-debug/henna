# HANA-LOGISTICS-001 — آمادگی اتصال سفارش حنا به سرویس لجستیک بیرونی

**مرحله:** Technical / Product Backlog  
**وضعیت:** آمادهٔ refinement؛ پیاده‌سازی runtime هنوز شروع‌پذیر نیست.

## تصمیم‌های مصوب مبنا

- طبق ADR-004 و ADR-046، عملیات ناوگان، تخصیص مأمور، مسیر و اجرای تحویل متعلق به سامانهٔ لجستیک بیرونی است؛ بازارگاه حنا مالک سفارش و رابط اتصال است.
- طبق ADR-005، در صورت پشتیبانی واقعی، مشتری روش دریافت حضوری یا ارسال را انتخاب می‌کند؛ در سفارش ارسالی مجری حمل را لجستیک تعیین می‌کند.
- شناسهٔ سفارش حنا و `deliveryJobId` شناسه‌های جدا هستند. وضعیت حمل باید از پاسخ یا رویداد معتبر سرویس بیاید.
- درآمد حنا و درآمد کسب‌وکار لجستیک جدا می‌مانند؛ این سند مبلغ یا تسویه‌ای تعیین نمی‌کند.

## مشاهدهٔ مخزن

در شاخهٔ فعلی مدل اجرایی سفارش، delivery job، adapter یا webhook لجستیک وجود ندارد. ADR-004 رابط‌هایی مانند `CoverageCheck`, `DeliveryQuote`, `CreateDeliveryJob`, `GetDeliveryJob`, `CancelDeliveryJob`, `DeliveryStatusEvent`, `ProofOfDelivery` و `Reconciliation` را به‌عنوان قرارداد پیشنهادی فهرست می‌کند؛ فهرست وضعیت نمونه در همان ADR نهایی اعلام نشده است.

## مرز این مرحله

این PR فقط قرارداد کاری و وابستگی‌های backlog را روشن می‌کند. endpoint، status enum، عملیات ادمین، پنل ناوگان، migration، سفارش، قیمت حمل یا اطلاعات نمایشی نمونه نمی‌سازد. بخش Admin / Logistics تا زمان افزوده‌شدن و تأیید frameهای خودش در Figma، UI آمادهٔ پیاده‌سازی ندارد.

## ترتیب Sprint پس از رفع وابستگی‌ها

1. تثبیت API contract و مدل تهدید.
2. پیاده‌سازی adapter و tests با sandbox ارائه‌دهنده؛ بدون fake provider به‌عنوان محیط production.
3. دریافت رویدادهای امضاشده، dedup و نگاشت به دادهٔ واقعی سفارش.
4. اتصال Admin read model پس از تصویب Figma و مجوزها.
5. QA سناریوهای timeout، retry، duplicate/out-of-order event، لغو قبل/بعد از handoff و عدم تحویل طبق ADRهای مربوط.
6. Stage با credentials و endpointهای sandbox؛ Release Approval جدا از آماده‌شدن کد.

## معیار ورود به کدنویسی

- یک Order domain و quote snapshot معتبر در حنا موجود باشد.
- ارائه‌دهنده، OpenAPI/payload، احراز هویت، idempotency، webhook signature، event catalog، sandbox و SLA مشخص باشند.
- سیاست نگهداری PII، دسترسی و audit مصوب باشد.
- Figma صفحهٔ Admin / Logistics و نقش‌های مشاهده/عملیات تأیید شده باشند.
- قوانین مالی/تسویهٔ لجستیک فقط در صورت نیاز به ledger با Finance/Operations تصویب شوند.

تا تحقق این معیارها هیچ سفارش، هزینهٔ حمل، مأموریت، تحویل، مدرک تحویل یا وضعیت عملیاتی در دادهٔ production ساخته یا ادعا نمی‌شود.
