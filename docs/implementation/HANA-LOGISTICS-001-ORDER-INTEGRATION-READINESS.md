# HANA-LOGISTICS-001 — آمادگی اتصال سفارش حنا به سرویس لجستیک مونو

**مرحله:** Technical / Product Backlog  
**وضعیت:** قرارداد سرویس‌دهنده بررسی شد؛ پیاده‌سازی مصرف‌کننده در حنا هنوز وابسته به Order domain و آماده‌شدن محیط اتصال است.

## تصمیم‌های مصوب مبنا

- طبق ADR-004 و ADR-046، عملیات ناوگان، تخصیص مأمور، مسیر و اجرای تحویل متعلق به مونو است؛ حنا مالک سفارش و مصرف‌کنندهٔ API مونو است.
- طبق ADR-005، در صورت پشتیبانی واقعی، مشتری روش دریافت حضوری یا ارسال را انتخاب می‌کند؛ در سفارش ارسالی مجری حمل را مونو تعیین می‌کند.
- شناسهٔ سفارش حنا با `delivery_request_id` و `mission_id` مونو متفاوت است؛ حنا باید نگاشت پایدار آن‌ها را نگه دارد.
- درآمد حنا و درآمد کسب‌وکار لجستیک جدا می‌مانند؛ این سند مبلغ یا تسویه‌ای تعیین نمی‌کند.

## بررسی فنی دو مخزن

مخزن مونو در شاخهٔ `main` قرارداد B2B مشترک `/v1` و پیاده‌سازی API مشتری را دارد. مسیرهای مرتبطی که در قرارداد و کد API دیده شدند:

| کاربرد | رابط مونو | وضعیت/نکته |
|---|---|---|
| دریافت درخواست حمل | `POST /v1/delivery-requests` | فقط رسید درخواست با `RECEIVED` را ثبت می‌کند؛ به معنی پذیرش یا ایجاد مأموریت نیست. `Idempotency-Key` اجباری است. |
| خواندن درخواست و آخرین وضعیت | `GET /v1/delivery-requests/{id}` | tenant-scoped؛ جزئیات تماس و مبدأ/مقصد را در پاسخ خلاصه برنمی‌گرداند. |
| گرفتن قیمت | `POST /v1/delivery-requests/{id}/quote` | مبلغ را کلاینت تعیین نمی‌کند. تا تأیید منبع/گواهی فاصله در مونو، پاسخ fail-closed برابر `422 QUOTE_EVIDENCE_UNVERIFIED` است؛ بنابراین قیمت عملیاتی هنوز قابل اتکا نیست. |
| ثبت زمان تعهدشده | `POST /v1/delivery-requests/{id}/promise` | باید فقط پس از نتیجهٔ معتبر ارزیابی و شواهد موردنیاز انجام شود. |
| تأیید مأموریت | `POST /v1/delivery-requests/{id}/confirm` | Quote معتبر و نسخهٔ جاری Promise لازم است؛ با موفقیت `mission_id` ایجاد می‌شود. |
| پیگیری | `GET /v1/missions/{id}` و timelineها | دادهٔ مشتری‌محور و محدود به tenant. |
| دریافت رویداد | ثبت webhook در `/v1/webhook-endpoints` | envelope امضاشده با HMAC و تحویل at-least-once در قرارداد مونو آمده؛ ارسال outbound به‌طور پیش‌فرض غیرفعال است و به پیکربندی کلید رمزگذاری نیاز دارد. |

احراز هویت B2B مونو برای فاز نخست با کلید اختصاصی هر مشتری از هدر `X-Mono-API-Key` و scope سمت سرور تعریف شده است. کلید خام فقط هنگام صدور داخلی یک‌بار نمایش داده می‌شود؛ هیچ endpoint عمومی صدور کلید وجود ندارد. کلید، endpoint عملیاتی یا sandbox در مخزن حنا ثبت نشده است.

در مخزن حنا، سند API خرید هنوز پیش‌نویس است و می‌گوید endpointهای آن پیاده‌سازی نشده‌اند. طبق گزارش فنی ثبت‌شده در backlog حنا، Order domain، مصرف‌کننده/adapter مونو و webhook ورودی حنا نیز هنوز در شاخهٔ مربوط به این کار وجود ندارند. بنابراین هنوز اتصال واقعی یا جریان سفارش سرتاسری نداریم.

## مرز این مرحله

این مرحله قرارداد فعلی مونو را به‌عنوان مبنای اتصال ثبت می‌کند. موارد زیر هنوز نتیجهٔ عملیاتی محسوب نمی‌شوند: پذیرش سفارش، قیمت قطعی، زمان تحویل، ایجاد مأموریت، وضعیت پیک، تحویل موفق، مدرک تحویل یا تسویه. هیچ دادهٔ خانوار/اعتبار حنا نباید برای لجستیک ارسال شود؛ فقط دادهٔ لازم برای اجرای حمل از API مجاز منتقل شود.

## ترتیب اجرای فنی

1. تهیهٔ قرارداد ماشین‌خوان از API موجود مونو و تست سازگاری payloadها و scopeها.
2. آماده‌کردن sandbox مونو، مشتری/شعبهٔ آزمایشی و کلیدهای محدود؛ secrets فقط در secret store محیط قرار گیرند.
3. تکمیل Order domain و API سمت حنا، سپس نوشتن adapter مونو در backend حنا؛ از مرورگر یا اپ مشتری به API مونو وصل نشود.
4. ثبت پایدار نگاشت `henna_order_id → mono_delivery_request_id → mono_mission_id` و اجرای فرمان‌ها با idempotency.
5. افزودن webhook receiver حنا برای HMAC، replay/dedup، ترتیب event و retry؛ تا آماده‌شدن receiver، پیگیری از API خواندنی مونو انجام شود.
6. اجرای تست سرتاسری sandbox برای خطاهای اعتبارنامه، timeout، retry، duplicate/out-of-order event، انقضای Quote و لغو مجاز؛ سپس Stage و QA طبق مجوز مستقل.

## معیار ورود به اتصال runtime

- Order domain و endpointهای حنا قابل استفاده باشند.
- OpenAPI/payload نسخه‌دار مونو و نگاشت هر فیلد با مدل حنا تثبیت شود.
- sandbox و credential محدود و قابل ابطال آماده باشند.
- مسیر منبع شواهد قیمت در مونو از حالت fail-closed خارج شده و قرارداد quote در محیط آزمون پاسخ معتبر بدهد.
- endpoint عمومی/شبکه‌ای حنا برای webhook با اعتبارسنجی HMAC و ثبت idempotent آماده باشد، یا تا آن زمان راهبرد polling API خواندنی مشخص باشد.
- تست‌های tenant isolation و عدم افشای دادهٔ اضافی در هر دو سمت برقرار باشند.

تا برآورده‌شدن این معیارها، اتصال production، قیمت/زمان قطعی و وضعیت واقعی تحویل ادعا یا ساخته نمی‌شود.
