# Frontend 029 — بازیابی صفحهٔ ذخیره‌شدهٔ فهرست وب پس از کاهش کالاهای منتشرشده

**دامنهٔ طرح مصوب:** همان خانه/مرور عمومی خریدار وب، فریم‌های `476:3`، `476:4`، `478:2` و `478:22` از Frontend 015. ادامهٔ [Frontend 023](HANA-FRONTEND-023.md)، [Frontend 027](HANA-FRONTEND-027.md) و اولویت وب در [ADR-047](../adr/ADR-047-BUYER-WEB-FIRST-IRAN-IOS-NATIVE-DEFERRED.md). هیچ صفحه، کنترل خرید یا API جدیدی ایجاد نمی‌شود.

## رفتار قابل‌مشاهده

وقتی خریدار لینکی از صفحهٔ دوم یا بعدترِ کاتالوگ را ذخیره کند، ممکن است تعدادی کالا بعداً از انتشار خارج شوند و آن صفحه دیگر وجود نداشته باشد. تا پیش از این گام، فهرست می‌توانست در صفحهٔ دوم با پیام «فعلاً کالایی برای نمایش نداریم» بماند، درحالی‌که صفحهٔ اول هنوز کالای منتشرشده داشت.

- فقط وقتی پاسخ **واقعاً معتبر ۲۰۰** برای همان `page`، `pageSize=20`، `total` معتبر و `items=[]` را نشان دهد و شروع صفحهٔ فعلی بیرون از `total` باشد، **همان ورودی history** به صفحهٔ اول اصلاح می‌شود؛ دسته و متن فارسی جست‌وجو حفظ می‌شوند و پیام بازیابی خوانا نمایش داده می‌شود. درخواست جدید صفحهٔ اول فقط از public catalog API است؛ محتوای قبلی یا محصول ساخته‌شده نمایش داده نمی‌شود.
- صفحهٔ دوم هنوز معتبر (`total >= 21`) بدون تغییر باقی می‌ماند. پاسخ ۵۰۳، قطعی یا JSON نامعتبر نمی‌تواند تعداد کالاهای منتشرشده را ثابت کند؛ URL و فیلتر حفظ می‌شوند و خطای واقعی نمایش داده می‌شود.
- اگر فهرست دستهٔ منتشرشدهٔ ۲۰۰ هم نشان دهد دستهٔ انتخاب‌شده حذف شده، بازیابی **دستهٔ Frontend 023** مقدم است؛ دو پیام متناقض و دو ورودی جدید در history ساخته نمی‌شوند.
- جست‌وجو/دسته/صفحهٔ جدید که کاربر انتخاب کند پیام قبلی را پاک می‌کند. برای `total=0`، صفحهٔ دوم ذخیره‌شده به صفحهٔ اول برمی‌گردد و **وضعیت خالی واقعی** باقی می‌ماند؛ قیمت، موجودی، امکان خرید یا شهر فعال فرض نمی‌شود.

## شواهد و محدودیت

`tests/web-buyer-navigation-smoke.mjs` شرایط معتبر/نامعتبر بازیابی صفحه را مستقل بررسی می‌کند. `tests/web-buyer-browse-browser-smoke.mjs` روی **Next.js production + Chromium واقعی**، با داده‌های HTTP حافظه‌ای **فقط CI**، صفحهٔ دومِ قبلاً معتبر، پاسخ ۵۰۳ و حفظ لینک، پاسخ معتبر پس از کاهش تعداد، بازیابی دسته/جست‌وجو/URL، خطای JSON و جست‌وجوی واقعاً خالی را آزمایش می‌کند. گیت‌های backend، web، mobile، Android و iOS موجود حذف یا به‌صورت صوری سبز نمی‌شوند.

این تغییر نه ادعای آزمون Safari روی آیفون واقعی دارد، نه PWA نصب‌شدنی یا انتشار عمومی محصول. دو طرح مرحلهٔ دوم ثبت‌نام فروشنده همچنان `DRAFT / NOT APPROVED` هستند.
