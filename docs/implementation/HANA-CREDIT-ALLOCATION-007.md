# Credit Allocation 007 — snapshot دامنه برای audit محاسبه

- **Business:** هر نتیجهٔ محاسبه باید بعداً به دستور منبع، مجوز و نسخهٔ فرمول/داده قابل بازسازی باشد.
- **Backlog:** Credit & Programs / immutable calculation provenance.
- **Sprint:** ساخت snapshot تغییرناپذیر از مراجع، نسخه‌ها، امتیازهای کمی‌شده، ورودی‌های جغرافیایی و breakdown مبلغ.
- **Code Review و CI:** شارژ برابر نباید دادهٔ نیاز/جغرافیا بسازد؛ نیازمحور باید نسخه‌ها، ضریب‌ها و امتیازها را حمل کند؛ زمان UTC و شناسهٔ محاسبه اجباری‌اند؛ چهار gate backend، web، mobile و Android.
- **Stage/QA/Release:** این PR فقط value object دامنه می‌سازد؛ جدول DB، سازوکار append-only، actor، idempotency یا ثبت پایدار ندارد.

## داده‌های snapshot

- منبع، مرجع منبع، مرجع دستور و مرجع مجوز نیازمحوری
- مدل و نسخهٔ policy
- برای نیازمحوری: نسخهٔ فرمول/scorer/geography، امتیازهای نگاشت‌شده، استان/شهر، urban/capital، MPI و بازه، ضرایب
- مبلغ پایه، سقف، محاسبه‌شده، قابل تخصیص و استفاده‌نشده با واحد ریال
- شناسه و زمان UTC محاسبه

جزئیات خام ارزیابی کیفی کپی نمی‌شود؛ امتیازهای کمی‌شده و نسخه‌های الگوریتم برای بازسازی ریاضی ثبت می‌شوند. snapshot مرجع اسناد را تأیید نمی‌کند و خودش در مخزن ماندگار نمی‌شود. گام بعدی پس از review باید طراحی migration و ذخیرهٔ immutable همراه با هویت actor و کلید تکرار را روی زیرساخت Credit واقعی انجام دهد.
