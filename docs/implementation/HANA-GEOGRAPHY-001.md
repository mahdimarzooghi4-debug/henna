# Geography 001 — دفترچهٔ استان و شهر قابل انتخاب، بدون ادعای پوشش عملیاتی

**هدف:** اولین گام فنیِ گسترش حنا «شهر به شهر» با شناسهٔ ثابت و مرز مستقل از کاتالوگ/فروشنده. این مرحله فقط دادهٔ مرجع مکان و API انتخاب شهر است.

## خروجی واقعی

- schema مستقل PostgreSQL به نام `geography` با جدول‌های `provinces` و `cities`، FK اجباری شهر به استان، UUID ثابت، نام فارسی، slug محدود، وضعیت `DRAFT | SELECTABLE`، یکتایی slug استان و یکتایی slug شهر **درون همان استان**؛ slug تکراری در استان دیگر مجاز است. constraintهای نام خالی/slug/وضعیت و indexهای جست‌وجو در migration مستقل `20260921010000_InitialGeography` هستند.
- `--apply-migrations` پس از Identity، Seller و Catalog، Geography را هم migrate می‌کند و readiness وجود/اعمال migration همه چهار ماژول را بررسی می‌کند. startup عادی، migration و seed اجرا نمی‌کند.
- `GET /api/v1/geography/provinces`: فقط استان‌های SELECTABLE، id/name/slug، بدون اطلاعات داخلی.
- `GET /api/v1/geography/cities?provinceId=<UUID>`: شناسه استان اجباری و یکتا است؛ 400 برای مقدار مفقود/تکراری/معیوب؛ پاسخ شهرهای SELECTABLE **فقط در استان SELECTABLE**، id/provinceId/name/slug. نتیجهٔ خالی واقعی 200 و `items: []` است.
- `GET /api/v1/geography/cities/{id}`: شهر پنهان، استان DRAFT یا شناسه ناشناخته، 404. پاسخ‌ها بدون cache؛ DB و migration نبودن باید به 503 readiness منجر شود و خطای دسترسی DB در API 503 است.
- هیچ endpoint عمومی برای اضافه‌کردن/فعال‌کردن استان یا شهر، هیچ شهر/استان واقعی یا نمونه‌ای در migration و هیچ وابستگی به ورود/نشست وجود ندارد.

## تفکیک مهم محصول

`SELECTABLE` **فقط به معنی مجازبودن انتخاب نام مکان در جریان نشانی آینده است، نه راه‌اندازی یک شهر**. شهر عملیاتی نیازمند پوشش فروشندهٔ تأییدشده، Offer/Stock، محدوده خدمت واقعی، لجستیک قراردادی، quote، پرداخت/تسویه و معیارهای انتشار شهر اول است. هیچ‌کدام با این flag فعال نمی‌شود؛ نام شهر فروشندهٔ پیش‌نویس نیز به‌طور خودکار به شهر موجودیت geography تبدیل نمی‌شود.

گام بعدی قراردادن شهر در آدرس و عرضهٔ فروشنده است، **پس از** تعیین منبع مرجع مکان، جزییات محدوده سرویس، قانون فعال‌سازی شهر و فریم‌های تاییدشدهٔ buyer/seller. برای تولید باید اپراتور مجاز اطلاعات استان/شهر معتبر را وارد کند و وضعیت SELECTABLE را طبق فرآیند مصوب تعیین کند؛ این مرحله پنل ادمین را جعل نمی‌کند.

## آزمون

`GeographyModelSnapshotTests` drift مدل و migration را قبل از اجرای migrations بررسی می‌کند؛ `GeographyReadApiTests` با API واقعی ASP.NET و PostgreSQL موقت CI، استان/شهر منتخب/مخفی، slug یکسان در استان‌های جدا، 400 query، 404 جزئیات، تغییر وضعیت استان بدون پاک‌کردن شهر و عدم افشای state و وضعیت delivery را آزمایش می‌کند. تست smoke، readiness و API عمومی را در فرآیند واقعی بررسی می‌کند.

**هیچ صفحهٔ جستجوی شهر، نقشه یا فهرست خرید به اسم طراحی مصوب Figma ساخته نشده است.** فیگمای متصل هنوز فریم‌های لازم برای این رابط‌ها را ندارد.
