# Seven-factor v1.1 — Independent Reviewed Intake Foundation

**State:** Backend foundation in Draft PR #165; neither data-admission nor live allocation authorization.
**Authority:** ADR-063 and ADR-064, accepted Product decisions.
**Historical baseline:** Six-factor V1 snapshots and profiles stay unchanged.

## Implemented
- Dedicated relational `allocation_learning.reviewed_seven_factor_assessments` records with immutable Version `HANA-NEEDS-BASED-ALLOCATION-v1.1`, original Source Formula/Dataset/Instruction identities, original geographic multiplier, and originating assessment ID.
- Each seven-feature review explicitly supplies all six raw 0–3 reviewed dimensions, including newly reviewed **non-housing** hardship; the seventh dimension is the explicitly evidenced OWNER/TENANT enum mapped by ADR-064 to 0/2.
- Housing, non-housing hardship, and the remaining five dimensions each require separate review evidence references, not a synthetic default or blind copy of historical hardship.
- Authorized ADMIN reviewer must reference an eligible first-party Henna allocation snapshot with valid historical runtime lineage. Manual/attributed snapshots cannot enter this review intake.
- PostgreSQL check constraints, FK, review-id idempotency with actor/payload replay binding, cross-replica safe insertion, and an append-only database trigger.
- Tests use PostgreSQL and assert authorization, legitimate review/replay, altered payload rejection, provenance checks, evidence obligations, append-only DB protection and separation from existing NeedLabels/TrainingRuns.

## Deliberate exclusions

No public mutation endpoint, new operational allocation, automatic cohort/dataset admission, new label, XGBoost seven-feature training, geographic parameter learning, model conversion, eligibility, wallet, funding confirmation, Production promotion or re-labeling of old rows.

The recorded evidence reference is only a **reference**; it does not itself prove source authenticity or independent validation. Before Production use, confirm the real evidence provider / reviewer workflow and trusted provenance, independent approved numeric Need Severity rubric, both-source financial confirmation required by ADR-063, temporal partition and fairness contracts, and an explicitly authorized staged rollout. Existing six-feature training and evaluation remain version-bound and do not read this new table.

## QA / safety notes

- Review corrections are new immutable rows with new ReviewId; no edit-in-place and no automatic latest selection.
- The geographic multiplier on the historical source remains frozen for traceability, not a license to change MPI production parameters.
- This is intentionally internal-only; an authorized HTTP API/UI requires a separate approved contract for secure evidence handling and permissions.
- No server-owned or synthetic fake evidence is generated by this implementation.
