# Credit Allocation 003 — دادهٔ استانی نسخه‌دار جغرافیا

- **Business:** برای شهر MPI شهری استان، برای سایر تقسیمات MPI روستایی استان، و برای شهر مرکز استان تعدیل ۲۰٪ اعمال می‌شود.
- **Backlog:** Credit & Programs / versioned provincial geography inputs.
- **Sprint:** ثبت ۳۱ ردیف استانی با منشأ، استخراج حداقل/حداکثر از ۶۲ مقدار MPI و ارائهٔ محاسبه‌گر دامنه.
- **Code Review و CI:** آزمون کامل‌بودن ۳۱ استان، بازهٔ شاخص‌ها، محدودهٔ نرمال‌سازی، شهر مرکز، شهر دیگر و ناحیهٔ غیرشهری؛ چهار gate backend، web، mobile و Android.
- **Stage/QA/Release:** این تغییر یک read model آماری خالص است. اتصال به درخواست تخصیص یا پرداخت عملیاتی در دامنهٔ آن نیست.

## منبع و محاسبه

داده از شیت «مبنای استانی» فایل ضرایب جغرافیاییِ تهیه‌شده از گزارش مرکز پژوهش‌های مجلس (شاخص MPI سال ۱۴۰۰) خوانده شده است: جدول شهری ۷، صفحات ۶۴–۶۵ و جدول روستایی ۸، صفحهٔ ۶۶. فراگیری، شدت و MPI هر دو گروه نگه داشته می‌شوند. دامنهٔ نرمال‌سازی از کمینه و بیشینهٔ همهٔ ۶۲ مقدار شهری/روستایی محاسبه می‌شود: ۰٫۰۰۰۱۴۴ تا ۰٫۲۱۱۳۶۵. سپس محاسبه‌گر Allocation 001 MPI منتخب را به بازهٔ ۰٫۸ تا ۱٫۲ می‌برد و ۲۰٪ مرکز استان پس از آن اعمال می‌شود.

شهر باید از registry جغرافیایی canonical اعتبارسنجی شده باشد؛ مقایسهٔ دقیق نام فقط برای شناسایی مرکز استان در این dataset است. برای ناحیهٔ غیرشهری مقدار روستایی استان استفاده می‌شود. هیچ ردیف شهر، بخش، شهرستان یا دهستان به جدول مرجع انتخاب مکان افزوده نمی‌شود.

## حدود استفاده

خود workbook کلیدهای تکراری و یک کد سلسله‌مراتبی خالی در فهرست ۶٬۵۸۸‌تایی تقسیمات دارد؛ بنابراین این PR فقط از شیت تجمیعی ۳۱ استان استفاده می‌کند. اطلاعات جدول، مقدار خام/نسبی مدل و منبع پژوهشی سال ۱۴۰۰ است؛ دادهٔ جدید سرشماری یا هزینهٔ زندگی نیست. ضریب خروجی نیز read model فرمول است و به‌تنهایی نرخ پرداخت مصوب یا تصمیم تخصیص نیست.

این تغییر دیتابیس/registry جغرافیا، API، وب، موبایل، eligibility، منبع اعتبار، wallet یا ledger را تغییر نمی‌دهد. نسخهٔ dataset همراه هر محاسبهٔ آینده باید ثبت شود و به‌روزرسانی داده نسخهٔ تازه می‌خواهد.
