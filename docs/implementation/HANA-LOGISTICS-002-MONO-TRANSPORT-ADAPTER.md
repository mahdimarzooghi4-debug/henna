# HANA-LOGISTICS-002 — لایهٔ انتقال سروری مونو

**مرحله:** Technical implementation
**وضعیت:** کلاینت محدود B2B و تست‌های قرارداد در شاخهٔ پیشنهادی پیاده شده‌اند؛ اتصال به چرخهٔ سفارش حنا، محیط آزمایشی و آزمون سرتاسری هنوز انجام نشده است.

## تغییر این مرحله

- `MonoLogisticsClient` فقط از backend حنا با `X-Mono-API-Key` به `/v1` متصل می‌شود.
- عملیات فعلی این لایه محدود به ایجاد درخواست حمل با `Idempotency-Key` و خواندن جزئیات درخواست است.
- درخواست تکراری خودکار ارسال نمی‌شود. فراخواننده برای تکرار همان فرمان باید همان کلید idempotency را نگه دارد.
- پاسخ ایجاد فقط در صورت `RECEIVED` پذیرفته می‌شود؛ این پاسخ به معنی پذیرش حمل یا ایجاد Mission نیست.
- خطاهای شبکه/timeout و پاسخ نامعتبر به خطای محدود و بدون متن خام provider تبدیل می‌شوند. اندازهٔ پاسخ هم سقف دارد.
- پیکربندی از `MonoLogistics:Enabled`, `MonoLogistics:BaseUrl` و `MonoLogistics:ApiKey` خوانده می‌شود. فعال‌شدن فقط با URL HTTPS و کلید حاضر است؛ کلید در endpoint وضعیت ادمین برگردانده نمی‌شود.
- فیلدهای اختیاری `null` در JSON ارسال نمی‌شوند تا با schema سخت‌گیرانهٔ Mono B2B v1 سازگار بمانند.

## مرزهای باقی‌مانده

این تغییر سفارش حنا را به مونو نمی‌فرستد و هنوز اتصال runtime کامل نیست. وضعیت مخزن در زمان این تغییر:

- Checkout حنا فقط `PICKUP` را قبول می‌کند و ارسال را با `DELIVERY_INTEGRATION_UNCONFIGURED` متوقف می‌کند.
- نگاشت پایدار فروشنده/شعبهٔ حنا به `branch_id` مونو وجود ندارد.
- مدل معتبر بسته‌بندی/بار مونو از اقلام سفارش حنا قابل استنتاج نیست و باید از دادهٔ واقعی کالا/بسته‌بندی ساخته شود.
- نگاشت پایدار شناسه‌های سفارش حنا به شناسه‌های مونو در
  [HANA-LOGISTICS-003](HANA-LOGISTICS-003-MONO-ORDER-CORRELATION.md) پیاده شده؛
  dispatcher هنوز آن را برای ارسال سفارش فراخوانی نمی‌کند.
- هیچ webhook receiver در حنا ساخته نشده است؛ قرارداد ماشین‌خوان فعلی مونو هم schema رویدادها را پوشش نمی‌دهد و ارسال outbound آن به پیکربندی جداگانه نیاز دارد. تا آماده‌شدن این بخش، polling قابل احراز از API خواندنی لازم است.
- صدور Quote مونو تا تأیید منبع شواهد فاصله fail-closed می‌ماند؛ بنابراین این مرحله قیمت یا زمان تحویل معتبر ایجاد نمی‌کند.

## وابستگی به محیط

برای آزمون واقعی باید Mono sandbox URL، کلید B2B محدود به scope لازم، شعبهٔ آزمایشی و شواهد quote معتبر فراهم شود. مقادیر محرمانه فقط در secret manager محیط قرار می‌گیرند. هیچ مقدار واقعی در مخزن یا تست‌ها ثبت نشده است.

## آزمون

تست‌های transport با handler درون‌حافظه‌ای، header احراز هویت و idempotency، serialize شدن قرارداد، رد پاسخ `ACCEPTED` در مسیر create، رد تنظیمات ناامن و خواندن مسیر جزئیات را بررسی می‌کنند. این تست‌ها شبیه‌سازی HTTP هستند و جای آزمون sandbox را نمی‌گیرند. اجرای محلی .NET در محیط فعلی ممکن نیست؛ CI باید build و تست‌ها را اجرا کند.
