# Identity 001 — قرارداد OTP و اتصال اولیه فرم‌ها به API

**مرحله:** پس از Frontend 002؛ این کار، ادامهٔ مسیر ورود است نه ماژول Fund. تغییرات اولیه Fund که بر اثر تفسیر نادرست «بعدی» افزوده شده بودند از شاخه اصلی خارج شدند.

## آنچه ساخته شده

- اعتبارسنجی مشترک در دامنه .NET برای شماره ایران (09 و ۱۱ رقم با تبدیل ارقام فارسی/عربی) و آزمون‌های مربوط؛ `ToString` شماره را در خروجی/log افشا نمی‌کند.
- `POST /api/v1/auth/otp/request` در ASP.NET Core؛ شماره نامعتبر 400، محدودکننده درخواست 429 و شماره معتبر تا اتصال سرویس واقعی پیامک **503** برمی‌گرداند. **کدی صادر، پیامکی ارسال یا حسابی ایجاد نمی‌شود**. محدودسازی فعلی بر اساس IP متصل است؛ پیش از استقرار پشت proxy باید ForwardedHeaders فقط برای پروکسی‌های مورد اعتماد و rate limit توزیع‌شده/حساب اعمال شود.
- مسیر server-side `/api/auth/otp/request` در Next.js؛ شماره واردشده از مرورگر به همان-origin proxy ارسال و سپس فقط در صورت پیکربندی `HANA_API_BASE_URL` به API حنا هدایت می‌شود. توکن/شماره در URL یا log قرار نمی‌گیرد.
- اپ Expo با متغیر عمومیِ صرفاً آدرس `EXPO_PUBLIC_HANA_API_BASE_URL` قادر به فراخوانی همان API است. در نبود تنظیم، یا پاسخ 503، پیام صریح عدم ارسال نمایش داده می‌شود. کلید محرمانه یا نام‌کاربری سرویس پیامک هرگز در `EXPO_PUBLIC_*` قرار نگیرد.

## راه‌اندازی توسعه

```sh
# ترمینال API
dotnet run --project apps/api/Hana.Api/Hana.Api.csproj

# ترمینال وب؛ فقط آدرس backend server-side
HANA_API_BASE_URL=http://127.0.0.1:5184 npm run web:dev

# ترمینال Expo در Android emulator؛ آدرس دستگاه با آدرس میزبان یکی نیست
EXPO_PUBLIC_HANA_API_BASE_URL=http://10.0.2.2:5184 npm run mobile:dev
```

پشتیبانی HTTP فقط در محیط محلی توسعه درنظر گرفته شده است؛ برای استقرار باید API HTTPS معتبر، gateway پیامک، storage چالش OTP با هش/انقضا/محدودیت تلاش، verification، ضد abuse سراسری، session و کنترل امنیتی نهایی تکمیل و آزمون شود. **در این مرحله متغیرها و URL نمونه نباید به‌عنوان آدرس تولید اعلام شوند**. متغیر Expo در زمان bundle ثابت می‌شود.

## اعتبارسنجی

GitHub Actions شامل تست واحد شماره، build .NET، smoke پاسخ‌های 400 و 503، typecheck/build وب، آزمون مسیر proxy در حالت سرویس غیرفعال و export باندل Expo است. در [اجرای GitHub Actions مربوط به اصلاح JSX موبایل](https://github.com/mahdimarzooghi4-debug/henna/actions/runs/35515881685)، **هر سه job بک‌اند/وب/موبایل موفق شدند**؛ **۱۴ آزمون اعتبارسنجی دامنه هویت پاس شدند** و تست 400/503 سمت API و proxy وب نیز اجرا شد. این آزمون‌ها تحویل پیامک واقعی یا ورود موفق را اثبات نمی‌کنند.
