# Frontend 016 — صفحهٔ اصلی اپ خریدار Expo و مرور عمومی کاتالوگ

## طراحی مصوب

مالک هر چهار فریم خانهٔ خریدار Frontend 010 را در گفت‌وگو صریحاً تأیید کرد. این مرحله دقیقاً دو وضعیت موبایل [476:4](https://www.figma.com/design/uREafnhmH5dDRwPraBOmuk/henna-platform?node-id=476-4) (خالی) و [478:22](https://www.figma.com/design/uREafnhmH5dDRwPraBOmuk/henna-platform?node-id=478-22) (دادهٔ API) را با رنگ‌های موجود `src/theme.ts` و لوگوی موجود Expo پیاده می‌کند. برچسب تاریخی DRAFT در بوم Figma وضعیت پیشین پیشنهاد است، نه لغو تأیید مالک.

## رفتار و مسیر واقعی

- `App.tsx` به‌جای نمایش ورود به‌عنوان تنها صفحه، با `BuyerBrowseScreen` عمومی آغاز می‌شود؛ ورود از هدر همین خانه و برگشت از صفحهٔ ورود ممکن است. فروشنده/ادمین همچنان صفحهٔ Expo ندارند.
- فقط `MobileCatalogClient.categories()` و `list({page,pageSize:20,categoryId,search})` عمومی مستقیماً به API واقعی منتشرشدهٔ ASP.NET درخواست می‌دهند. Authorization، Cookie و SecureStore در مسیر مرور کاتالوگ وجود ندارند؛ حداقل فیلدهای `id/categoryId/name/kind/description` مصرف می‌شوند.
- فهرست خالی با پاسخ **تأییدشدهٔ 200** نشان داده می‌شود؛ پاسخ خراب، 503، قطع شبکه و config نامعتبر با وضعیت unavailable و دکمهٔ تلاش دوباره نشان داده می‌شوند. دسته‌بندی‌ها و کالاها مستقلاً مجدداً دریافت می‌شوند.
- دسته‌بندی‌ها فقط از UUID موجود در پاسخ تأییدشده انتخاب می‌شوند؛ انتخاب همه categoryId را حذف می‌کند. جست‌وجوی حداکثر ۸۰ نویسه و فیلتر، صفحه را به ۱ برمی‌گردانند. دکمه‌های صفحه‌بندی از `total` و `pageSize` واقعی تبعیت می‌کنند؛ صفحهٔ قبلی به‌جای نتیجهٔ تازه نمایش داده نمی‌شود.
- `BuyerBrowseController` درخواست قبلی را با AbortController لغو می‌کند؛ پاسخ قدیمی پس از فیلتر/جست‌وجو/ترک صفحه نمی‌تواند وضعیت فعلی را تغییر دهد. `MobileCatalogClient` سیگنال لغو اختیاری می‌پذیرد، ۸ ثانیه timeout پیشین برقرار است.
- ورود OTP مصوب، SecureStore و بررسی دوبارهٔ نشست در foreground در صفحهٔ ورود قبلی باقی‌اند. ترک صریح صفحهٔ ورود و بازگشت به مرور عمومی آن صفحه را unmount می‌کند؛ ورود بعدی نشست را از سرور مجدداً بررسی می‌کند. قطع شبکه در مسیر کاتالوگ هرگز به معنای خروج از حساب نیست.

## شواهد و محدوده

`tests/mobile-buyer-browse-smoke.mjs` هماهنگ‌کنندهٔ **واقعی shipping** و کلاینت HTTP واقعی اپ را با transport حافظه‌ای فقط CI بررسی می‌کند: خالی، دسته و محصول دارای داده، مخفی‌ماندن private fields، جست‌وجو و category واقعی، صفحه‌بندی، خطاهای 503/network/malformed، retry، حذف دسته از انتشار، لغو درخواست و پاسخ دیررس/حذف صفحه. CI موبایل `tsc --noEmit` و `expo export --platform android` را هم اجرا می‌کند. **این تست روی دستگاه، شبیه‌ساز یا لمس واقعی native UI اجرا نمی‌شود**؛ Android/iOS release و smoke روی دستگاه نیازمند مرحلهٔ جدا هستند.

هنوز دادهٔ منتشرشدهٔ production وارد نشده و SMS provider واقعی متصل نیست. هیچ قیمت، موجودی، فروشنده، جغرافیای سرویس‌پذیر، جزئیات کالا، سبد، checkout، خرید و پرداخت از API کاتالوگ عمومی قابل نتیجه‌گیری نیست؛ این صفحه فقط مرور محتوای منتشرشده است.
