# اتصال خرید اپ خریدار — لایه ارتباط

`apps/mobile-consumer/src/mobile-commerce.ts` کلاینت بومی خرید را فراهم می‌کند. قراردادهای مالی و DTO مشترک وب/اپ در `packages/buyer-commerce/contracts.ts` هستند؛ مسیرها فقط به API خریدار محدودند. این مرحله هنوز کلاینت را به صفحات اپ وصل نمی‌کند و ادعای تکمیل رابط خرید موبایل ندارد.

- توکن در هر درخواست محافظت‌شده از adapter همان SecureStore خوانده می‌شود و به UI برنمی‌گردد. پیشنهادهای عمومی بدون خواندن توکن دریافت می‌شوند.
- خطای شبکه/503، توکن را پاک نمی‌کند. 401 فقط در صورت برابر ماندن توکن ذخیره‌شده با توکن ردشده، حذف آن را درخواست می‌کند. خواندن/پاک‌سازی ناموفق به خطای سرویس تبدیل می‌شود.
- کلید UUID هر mutation باید یک بار با منبع امن بومی تولید شود. `mobileCommerceIntent` مسیر، بدنه و کلید را منجمد می‌کند؛ برای پاسخ نامشخص باید همان intent حفظ شود. کلاینت retry خودکار ندارد.
- پاسخ‌های مالی، وضعیت و زمان با همان parser وب اعتبارسنجی می‌شوند. مبلغ خارج از دقت عدد صحیح، صفحه اشتباه و پاسخ نامعتبر به لیست خالی تبدیل نمی‌شوند.
- redirect:error درخواست می‌شود و نتیجه redirect یا URL متفاوت رد می‌شود. اجرای redirect در transportهای React Native باید روی دستگاه نیز بررسی شود؛ رد نتیجه به‌تنهایی تضمین عدم دنبال شدن redirect در همه نسخه‌های بومی نیست.
- در نبود Content-Length، سقف ۵۱۲KB پس از دریافت متن بررسی می‌شود؛ این کنترل سقف حافظه transport بومی را تضمین نمی‌کند. خطاهای JSON بیش از ۴KB رد می‌شوند.

CI با doubles جداگانه API/SecureStore رفتار همین کلاینت را بررسی می‌کند؛ این تست اثبات خرید زنده یا اتصال پیامک/بانک/لجستیک نیست. گام بعد، اتصال صفحات سبد/تسویه/سفارش‌ها، تولید UUID بومی، بررسی foreground نشست و اجرای مسیر روی دستگاه است.
