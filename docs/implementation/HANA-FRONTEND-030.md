# Frontend 030 — فونت و تکمیل تجربهٔ ورود اپ خریدار

## تغییرات رابط

- فونت فارسی Vazirmatn با وزن‌های ۴۰۰ و ۷۰۰ و مجوز OFL به دارایی‌های Expo اضافه شد. اپ پیش از نمایش صفحه‌ها فونت را بارگذاری می‌کند؛ کامپوننت متن حنا براساس وزن درخواستی، نسخهٔ درست فونت را انتخاب می‌کند.
- گام واردکردن کد OTP حالا صفحهٔ تأیید شماره با توضیح کد شش‌رقمی، شمارهٔ پوشیده‌شده، صفحه‌کلید عددی، تکمیل خودکار کد پیامک در سیستم‌عامل، دکمهٔ «تأیید و ورود»، ارسال دوباره و ویرایش شماره است. این چیدمان از طراحی ورود حنا پیروی می‌کند؛ هنوز فریم مستقل تأیید OTP در Figma تأیید نشده است.
- در جزئیات کالا UUID دسته به کاربر نشان داده نمی‌شود. اگر نام دسته از فهرست عمومی API در دسترس باشد همان نام نمایش داده می‌شود؛ شناسهٔ خام هیچ‌وقت جای نام یا متن نمونه را نمی‌گیرد.
- دکمهٔ «ثبت‌نام فروشگاه» به مسیر واقعی وب `/seller/register` باز می‌شود. مبدأ وب از `EXPO_PUBLIC_HANA_WEB_BASE_URL` خوانده می‌شود؛ HTTP فقط برای میزبان شبیه‌ساز در توسعه پذیرفته می‌شود و production به HTTPS نیاز دارد.

## مرزهای اتصال

- ارسال واقعی SMS همچنان به تنظیم provider در سرور وابسته است. این تغییر رابط OTP را آماده می‌کند و ادعای ارسال پیامک یا ورود عملیاتی ندارد.
- برای نسخهٔ انتشار، origin وب واقعی باید در `EXPO_PUBLIC_HANA_WEB_BASE_URL` هنگام build اپ تنظیم شود. فایل `.env.example` فقط مقدار توسعهٔ Android Emulator را نشان می‌دهد.
- فریم‌های عمومی مرور و جزئیات همچنان براساس دادهٔ واقعی API کار می‌کنند؛ قیمت، موجودی، پیشنهاد فروشنده، سبد یا خرید به اپ اضافه نشده است.

## شواهد

- `npm run mobile:typecheck`
- ۳۱ تست OTP، کاتالوگ خریدار، جزئیات و ساخت URL ایمن ثبت‌نام فروشگاه موفق شدند.
- `npm run mobile:export:android` موفق شد؛ فونت‌های محلی در bundle Android قرار گرفتند.
- این شواهد build و منطق هستند؛ لمس UI روی دستگاه فیزیکی در این مرحله انجام نشده است.
