# Frontend 030 — Organization Portal Dashboard

## Scope

مسیر وب `/organization` برای مدیران سازمان به داده واقعی CommerceDb متصل است.

فریم پایه از بخش Organization Portal فیگما گرفته شده است؛ برای read model عملیاتی
وضعیت/طرح‌ها فریم مستقل تأییدشده‌ای وجود ندارد، بنابراین از توکن‌ها و الگوهای فعلی
حنا استفاده شده و ادعای تطابق پیکسلی کامل نمی‌شود.

## مرز دسترسی

مرورگر از `GET /api/organization/dashboard` استفاده می‌کند و bearer را نمی‌بیند.
BFF فقط cookie امن نشست را server-to-server تبدیل می‌کند.

بک‌اند `GET /api/v1/organization/dashboard` را فقط وقتی برمی‌گرداند که actor
عضویت فعال `MANAGER` برای حداقل یک سازمان داشته باشد. نقش ADMIN به‌تنهایی جای
عضویت سازمان را نمی‌گیرد.

خروجی فقط شامل این داده‌های لازم است:

- شناسه و نام سازمان‌های تحت مدیریت
- تعداد مدیر/مشمول فعال و تعداد طرح‌های همان سازمان
- نام طرح، مبلغ ثبت‌شده، مانده تخصیص، تاریخ انقضا و تعداد دسته مجاز
- تعداد اعلان خوانده‌نشده و تیکت باز خود مدیر

`registrationReference`، `fundingReference` و شناسه حساب مشمولان به UI داده
نمی‌شوند.

## رفتار UI

- هیچ نام سازمان، تعداد طرح، بودجه یا وضعیت sync ساختگی در runtime وجود ندارد.
- loading، عدم مجوز، outage و پاسخ نامعتبر از حالت empty واقعی جدا هستند.
- صفحه RTL است، Vazirmatn و لوگوی محلی حنا را استفاده می‌کند.
- تخصیص یا تغییر منبع مالی از این dashboard انجام نمی‌شود؛ آن عملیات همچنان به
  مجوز و ورودی مصوب مالی نیاز دارد.

## QA

- parser پاسخ‌های cross-organization یا malformed را fail-closed رد می‌کند.
- BFF با HTTPS upstream ایزوله، عدم نشت cookie و حذف فیلدهای اضافی خصوصی تست می‌شود.
- تست PostgreSQL ثابت می‌کند مدیر سازمان فقط tenant خود را می‌بیند و بعد از revoke
  عضویت، همان مسیر 403 می‌دهد.

## محدودیت

همگام‌سازی افراد از سامانه بیرونی سازمان، تأمین مالی واقعی و reconciliation خارجی
هنوز ورودی/اتصال بیرونی می‌خواهند. این dashboard آن‌ها را «فعال» یا «موفق» فرض
نمی‌کند.
