# Geography 003 — پیش‌نمایش و ورود کنترل‌شدهٔ مرجع استان و شهر

**مسئله:** Geography 001 دفترچهٔ مکانِ PostgreSQL و Geography 002 دسترسی خریدار در وب/اپ را پیاده کردند، اما عمداً استان و شهر نمونه یا تولیدی در migration وارد نشده بود. برای تهیهٔ دادهٔ واقعی از منبع معتبر و نسخهٔ بررسی‌شده، مسیر محدودِ CLI اپراتور ساخته شد؛ نه API عمومی و نه پنل مدیریتِ حدسی.

## قرارداد فرمان عملیاتی

با `ConnectionStrings__IdentityDb` معتبر از محیط/secrets و پس از اجرای مستقل `--apply-migrations`:

- `dotnet run --project apps/api/Hana.Api/Hana.Api.csproj -- --geography-preview /absolute/path/locations.json`: بررسی JSON و تطبیق با DB، شمارش ردیف‌های جدید/تغییریافته **بدون نوشتن**.
- `dotnet run --project apps/api/Hana.Api/Hana.Api.csproj -- --geography-apply /absolute/path/locations.json --expected-sha256 <sha256-from-preview>`: اعمال صریح ورودی تأییدشده، اتمیک در یک تراکنش PostgreSQL؛ قفل جدول، ورود همزمانِ اپراتوری را سریال می‌کند. تکرار ورودی بی‌تغییر، ردیف تکراری نمی‌سازد.
- فایل باید `provinces` و `cities` هر دو آرایه را صریح داشته باشد؛ حداکثر ۱۰۰ استان، ۵۰۰۰ شهر و ۲ MiB. حداقل یک ردیف لازم است. schema سخت‌گیرانه است؛ کلید اضافه مانند `launched`، `stock` یا `deliveryAvailable` رد می‌شود. فیلدهای استان: `id`، `name`، `slug`، `state`؛ شهر: `id`، `provinceId`، `name`، `slug`، `state`.
- `id` باید UUID غیرصفر، نام غیرخالی و حداکثر ۱۲۰ نویسه، slug لاتین lowercase/عدد/خط‌تیره و حداکثر ۱۰۰ نویسه، `state` فقط `DRAFT` یا `SELECTABLE` باشد. slug استان در همهٔ استان‌ها یکتا و slug شهر فقط **در همان استان** یکتاست. ارجاع شهر به استان باید در فایل یا DB وجود داشته باشد. انتقال شناسهٔ شهر موجود به استان دیگر ممنوع است؛ تصحیح چنین رخدادی نیازمند بازبینی مستقل هویت مکانی است.
- اگر یکی از ردیف‌ها نامعتبر باشد، همهٔ batch قبل از تغییر ردیف‌های EF رد می‌شود. خطای PostgreSQL نیز تراکنش را rollback می‌کند. حذف نام یک مکان از فایل، **حذف یا غیرفعال‌سازی خودکار** نیست؛ برای پس‌گرفتن انتخاب، state را صریح به `DRAFT` تغییر دهید. استان DRAFT، شهرهایش را در API عمومی پنهان می‌کند، بدون آنکه رکورد شهر پاک شود.

## مثال صرفاً قالب (نه seed)

```json
{
  "provinces": [
    {
      "id": "2fd59aad-5834-4717-9462-c5e520dd7a31",
      "name": "نام استان بررسی‌شده",
      "slug": "reviewed-province",
      "state": "DRAFT"
    }
  ],
  "cities": [
    {
      "id": "40a9a026-f3f8-4366-b164-d43b52b641be",
      "provinceId": "2fd59aad-5834-4717-9462-c5e520dd7a31",
      "name": "نام شهر بررسی‌شده",
      "slug": "reviewed-city",
      "state": "DRAFT"
    }
  ]
}
```

**اجرای تولیدی:** منبع و صحت فهرست استان/شهر، UUID پایدار، مسئول و اختیار تأیید، hash نسخهٔ فایل، پشتیبان‌گیری و مجوز دسترسی به runner/DB باید در فرآیند اپراتوری واقعی کنترل شوند. طبق [Operations 001](HANA-OPERATIONS-001.md)، preview اکنون SHA-256 فایل را چاپ می‌کند و apply بدون digest تأییدشدهٔ **همان bytes** رد می‌شود. hash، مجوز و هویت شخص تأییدکننده نیست و نباید اجرای apply اتوماتیک در production فعال شود. وضعیت `SELECTABLE` فقط برای انتخاب هویت مکانی است، نه فعال‌سازی خرید در شهر، خدمت‌رسانی فروشنده، لجستیک، پرداخت یا پوشش محله.

## آزمون پذیرش

`GeographyImportApiTests` روی PostgreSQL موقت CI و ASP.NET واقعی: پیش‌نمایش بدون تغییر، اعمال، idempotency، فیلد اضافی، شناسه/slug تکراری، ارجاع بدون استان، reparent، state غیرمجاز، عدم تغییر نیمه‌کاره، پوشاندن و بازیابی استان/شهر، حفظ ردیف‌های حذف‌شده از فایل و عدم نمایش وضعیت/تحویل در API عمومی را می‌سنجد. smoke مستقل، خود فرمان‌های preview/apply را با JSON موقت CI اجرا می‌کند. هیچ دادهٔ CI در migration یا build محصول seed نشده است.

**هنوز اجرا نشده:** تأمین/تأیید مرجع واقعی استان و شهر برای production، پنل ادمین و audit تأیید محتوا، فریم‌های مصوب UI انتخاب نشانی، مرجع محدوده خدمت فروشنده، عرضه/قیمت/موجودی و معیار فعال‌سازی تجاری شهر.
