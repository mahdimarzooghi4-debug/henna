# Credit Allocation 006 — اتصال دستور منبع به مدل تخصیص

- **Business:** شارژ برابر طبق دستور صریح منبع قابل اجراست؛ نیازمحوری فقط برای صندوق نیکوکاری حنا یا با مجوز ثبت‌شدهٔ خیر فعال می‌شود. دستور سازمان برای این گام به شارژ برابر محدود است.
- **Backlog:** Credit & Programs / bind funding instruction to allocation model.
- **Sprint:** مدل دامنه برای منبع، مدل تخصیص و شناسه‌های دستور/مجوز؛ resolver که فقط مسیر مجاز را اجرا کند و مراجع را در خروجی حمل کند.
- **Code Review و CI:** مسیر سازمانیِ شارژ برابر، صندوق حنا، خیر با/بدون مجوز، ناسازگاری مدل و مراجع خالی؛ چهار gate backend، web، mobile و Android.
- **Stage/QA/Release:** این PR اعتبار یا اصالت اسناد را اثبات نمی‌کند و پایگاه‌داده، endpoint، جریان اداری یا audit پایدار نمی‌سازد.

## قواعد v1

- هر ورودی باید منبع، مدل تخصیص و مرجع دستور غیرخالی داشته باشد؛ مقدار پیش‌فرضی وجود ندارد.
- سازمان در این نسخه فقط می‌تواند شارژ برابر را انتخاب کند.
- صندوق نیکوکاری حنا می‌تواند صریحاً نیازمحور را انتخاب کند.
- خیر فقط با مرجع مجوز نیازمحوری می‌تواند از فرمول استفاده کند؛ در غیر این صورت تخصیص نیازمحور رد می‌شود.
- resolver فقط تابع محاسبهٔ منطبق با دستور را فراخوانی می‌کند و مراجع منبع، دستور و مجوز را کنار نتیجه برمی‌گرداند.

مراجع فقط شناسه‌اند؛ این کد بررسی نمی‌کند که سند واقعی، امضاشده یا از مرجع قابل اعتماد آمده باشد. لایهٔ application باید پیش از ساخت instruction مجوز را از فرایند مورد اعتماد احراز کند. برای audit عملیاتی باید instruction و خروجی به‌صورت پایدار و immutable ثبت شوند؛ این کار عمداً در این PR نیست و پیش از آن باید مدل برنامه/منبع و چرخهٔ تأیید مشخص شود.
