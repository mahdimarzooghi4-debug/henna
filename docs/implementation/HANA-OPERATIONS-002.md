# Operations 002 — رسید پایدار ورود کاتالوگ و جغرافیا، هم‌تراکنش با تغییرات

## مشکل و اصلاح

Operations 001 فایلِ تأییدشده را به SHA-256 دقیق bytes مقید کرد، اما پس از اجرای CLI سند پایدار قابل پرس‌وجویی در DB نبود که نشان دهد **چه ورودی‌ای واقعاً اعمال شد و چند رکورد ایجاد/تغییر کرد**. این مرحله برای هر schema یک جدول `import_receipts` و migration مستقل اضافه می‌کند؛ نه HTTP عمومی و نه دادهٔ ساختگی.

هر `--catalog-apply` و `--geography-apply` موفق، هم‌زمان با تغییر رکوردهای آن batch در **همان تراکنش PostgreSQL** یک receipt می‌نویسد:

- `id`: UUID یکتای همان اجرا؛
- `content_sha256`: SHA-256 کوچکِ JSON UTF-8 دقیق ورودی؛ ۶۴ رقم hex، بدون ذخیرهٔ محتوای فایل؛
- `applied_at_utc`: زمان UTC اجرای اعمال؛
- `new_parents`, `changed_parents`, `new_children`, `changed_children`: شمارش واقعی تغییرها؛ در Catalog به‌ترتیب دسته‌ها/محصولات و در Geography استان‌ها/شهرها.

**پیش‌نمایش، ورودی نامعتبر و rollback، رسید موفق ندارند.** apply با هش وضعیت DB قدیمی نیز پیش از ثبت receipt رد می‌شود (Operations 003). اجرای تکراری موفق—even وقتی همه شمارش‌ها صفر هستند—رسید تازه دارد تا عملیاتی‌بودن اجرای مجدد مشخص بماند؛ خود هویت محصولات/شهرها تکرار نمی‌شود. اگر درج receipt یا ذخیرهٔ رکوردها شکست بخورد، کل تراکنش rollback می‌شود. read API و مدل خروجی public تغییر نمی‌کنند؛ رسید از طریق دسترسی محدود DBA/اپراتور به دو schema قابل بررسی است.

برای راه‌اندازی نسخهٔ جدید، ابتدا `--apply-migrations` را جداگانه اجرا کنید و سپس دستورات preview و apply دو-هشی در [Operations 003](HANA-OPERATIONS-003.md) را اجرا کنید. startup عادی schema ایجاد نمی‌کند؛ readiness تا اعمال هر دو migration تازه 503 می‌دهد. CI drift snapshot، مهاجرت تکراری، preview بدون receipt، apply و تکرار با دو receipt مختلف و رد batch معیوب بدون receipt را با PostgreSQL واقعی تست می‌کند.

## مرز ممیزی

این جدول **رسید اجرای واردکننده** است و هنوز «audit غیرقابل‌حذف/امضاشده با هویتِ احرازشدهٔ تأییدکننده» نیست. کاربری که دسترسی مستقیم نوشتن به DB دارد می‌تواند receipt را تغییر دهد یا حذف کند؛ باید در deployment مجوزها، backup و audit سطح DB مستقل محدود شوند. CLI هنوز reviewer را از IAM معتبر دریافت نمی‌کند و ادعای اینکه یک شخص خاص محتوا را تأیید کرده، ثبت نمی‌شود. SHA-256 به تنهایی اثبات اصالت منبع، صحت محتوای تجاری یا ایمن بودن فروش/تحویل شهر نیست. بدون منبع دادهٔ مصوب و نقش/دسترسی قابل بررسی، import تولیدی نباید خودکار شود.
