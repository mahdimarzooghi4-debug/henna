# ADR-004 — لجستیک حنا کسب‌وکار متصل و مستقل از هسته بازارگاه

**وضعیت:** بخش اصل معماری تصویب‌شده توسط مالک محصول؛ روش‌های مجاز تحویل هنوز نیازمند تصمیم جدا  
**تاریخ ثبت:** ۲۰۲۶-۰۹-۱۹  
**حوزه:** Marketplace, Logistics Integration, Seller, Fulfillment, City Rollout

## تصمیم تصویب‌شده

«لجستیک حنا» خود یک **کسب‌وکار/سامانه عملیاتی متصل به حنا** است. بازارگاه حنا باید از طریق **قرارداد و رابط یکپارچه‌سازی مشخص** با آن تعامل کند، نه اینکه منطق عملیاتی لجستیک را داخل ماژول سفارش یا پنل فروشنده بازارگاه ادغام و به آن گره بزند.

این تصمیم به‌خودی‌خود درباره مالکیت حقوقی کسب‌وکار لجستیک، ساختار شرکتی، اینکه تنها روش تحویل حنا باشد، یا امکان تحویل توسط فروشنده/حضوری حکمی نمی‌دهد؛ این موارد باید جداگانه توسط مالک محصول تأیید شوند.

## مرز مالکیت دامنه

| بازارگاه حنا | لجستیک حنا |
|---|---|
| مالک سفارش خرید، خریدار، فروشنده منتخب، اقلام، مبلغ فروش و وضعیت تجاری سفارش | مالک عملیات مأموریت ارسال/تحویل، تخصیص مأمور، مسیر، اجرای حمل و رویدادهای عملیاتی تعریف‌شده در قرارداد |
| درخواست پیشنهاد حمل و ثبت درخواست حمل برای سفارش معتبر | اعلام پوشش، ظرفیت/پذیرش مأموریت، هزینه/زمان تخمینی طبق قرارداد، شناسه مأموریت و تغییرات وضعیت |
| دریافت وضعیت برای نمایش پیگیری خریدار/فروشنده و رسیدگی | ارسال رویداد وضعیت، شکست، عدم امکان دریافت/تحویل و مدرک تحویل طبق سیاست مصوب |
| اعمال سیاست مالی مصوب حمل در Quote و ثبت نهایی سفارش | صدور/ثبت هزینه حمل و صورتحساب بین دو کسب‌وکار مطابق قرارداد مصوب |

**هویت مشترک برند یا مالکیت تجاری نباید باعث دسترسی مستقیم لجستیک به تمام جداول کاربران/سازمان‌ها/اعتبارات شود.** حداقل داده لازم برای مأموریت ارسال از طریق API و کنترل مجوز تبادل شود.

## قرارداد یکپارچه‌سازی پیشنهادی

`CoverageCheck`, `DeliveryQuote`, `CreateDeliveryJob`, `GetDeliveryJob`, `CancelDeliveryJob`, `DeliveryStatusEvent`, `ProofOfDelivery`, `Reconciliation`.

شناسه‌های `orderId` و `deliveryJobId` متمایز باشند؛ ایجاد مأموریت و callback باید idempotent و با correlation ID باشند. تحویل موفق صرفاً با رویداد تأییدشده و سیاست مصوب به وضعیت سفارش نگاشت شود. خطا یا تأخیر لجستیک، سفارش و نتیجه پرداخت را بی‌صدا حذف یا موفق اعلام نکند.

حداقل وضعیت‌های نمونه (غیرنهایی): `REQUESTED`, `ACCEPTED`, `PICKUP_PENDING`, `PICKED_UP`, `IN_TRANSIT`, `DELIVERED`, `FAILED`, `CANCELLED`. قرارداد حالت، مسئولیت لغو، هزینه شکست، مرجوعی و مدرک تحویل هنوز نیازمند تصویب‌اند.

## اثر توسعه شهر به شهر

بازارگاه می‌تواند شهر را فقط پس از ثبت پوشش و آمادگی واقعی لجستیک/سایر روش‌های تحویل مصوب فعال کند. یکپارچه‌سازی واحد و تنظیمات `CityLaunchConfig` برای پوشش، ظرفیت و روش تحویل شهر استفاده شود؛ برای هر شهر نسخه متفاوت و منفصل از هسته بازارگاه ساخته نشود.

## پرسش‌های باقی‌مانده (در این ADR پاسخ داده نشده‌اند)

1. آیا علاوه بر لجستیک حنا، تحویل توسط فروشنده و دریافت حضوری هم مجازند؟
2. انتخاب روش تحویل با مشتری است یا بر اساس عرضه/شهر/نوع کالا محدود می‌شود؟
3. قرارداد دریافت هزینه، صورتحساب، تسویه، بیمه/مسئولیت، مرجوعی و SLA دو کسب‌وکار چیست؟
4. آیا لجستیک حنا مخزن/سامانه/تیم مستقل و API موجود دارد یا باید جداگانه ساخته شود؟
