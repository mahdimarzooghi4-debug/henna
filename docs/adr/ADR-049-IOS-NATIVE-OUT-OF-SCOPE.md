# ADR-049 — خروج iOS Native از scope فعلی حنا

**وضعیت:** مصوب مالک محصول و لازم‌الاجرا  
**تاریخ ثبت:** ۲۰۲۶-۱۰-۰۶  
**حوزه:** Delivery Scope, Buyer Web, Android Consumer, iOS Native, CI/QA  
**جایگزین:** [ADR-047 — اولویت وب و تعویق iOS](ADR-047-BUYER-WEB-FIRST-IRAN-IOS-NATIVE-DEFERRED.md)

## تصمیم مالک

- پیاده‌سازی **iOS Native** از scope فعلی محصول حنا خارج است.
- تا وقتی مالک محصول دوباره به‌صورت صریح این تصمیم را تغییر ندهد، تیم/عامل توسعه نباید برای iOS قابلیت جدید، رفع باگ اختصاصی، build بومی، Simulator QA، signing، App Store delivery، deep-link native gate یا CI اختصاصی ایجاد یا دنبال کند.
- شکست یا ناسازگاری اختصاصی iOS نباید مانع ادامهٔ توسعه، Code Review، Stage یا QA مسیرهای مصوب حنا شود.
- تجربهٔ کاربران آیفون در scope فعلی از مسیر **وب واکنش‌گرا** دنبال می‌شود. این تصمیم به‌خودی‌خود ادعای PWA، Safari compatibility کامل، App Store availability یا قابلیت native iOS ایجاد نمی‌کند.
- اپ مصرف‌کنندهٔ Android و تجربهٔ Web همچنان در scope باقی می‌مانند.
- کد مشترک mobile فقط زمانی باید تغییر کند که برای Android یا قرارداد مشترک محصول لازم باشد؛ تغییر صرفاً برای سازگاری iOS مجاز نیست.

## اثر اجرایی

1. job و gate اختصاصی iOS از GitHub Actions حذف می‌شود.
2. bundle/build اختصاصی iOS از CI عادی حذف می‌شود.
3. smoke testها و harnessهای native iOS از مسیر فعال پروژه خارج می‌شوند.
4. تغییرات فنی‌ای که فقط برای رفع failure اختصاصی iOS افزوده شده‌اند و برای Android/Web لازم نیستند، نگه‌داری نمی‌شوند.
5. نبود CI یا build iOS نباید به‌عنوان نقص Release فعلی حنا گزارش شود.

## شرط بازفعال‌سازی

iOS Native فقط با **دستور صریح جدید مالک محصول** دوباره وارد scope می‌شود. در آن صورت باید قرارداد محصول، backlog، CI/QA و مسیر انتشار آن دوباره به‌صورت مستقل تعریف شوند. تا پیش از آن، «رفع iOS» یا «تکمیل iOS» نباید به‌عنوان کار بعدی پیشنهاد یا اجرا شود.
