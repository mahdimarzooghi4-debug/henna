# ADR-045 — پشته فناوری حنا: ASP.NET Core / .NET 10 LTS برای بک‌اند

**وضعیت:** تصویب‌شده توسط مالک محصول؛ مبنای شروع پیاده‌سازی در آینده، نه ادعای ایجاد کد یا استقرار  
**تاریخ ثبت:** ۲۰۲۶-۰۹-۲۰  
**حوزه:** Engineering, Backend, Frontend, Mobile, Data, Architecture, Deployment  
**مرتبط:** [معماری کامل حنا](../architecture/HANA-FULL-PRODUCT-NATIONAL-ARCHITECTURE-v1.0.md)، [ADR-004 — جدایی کسب‌وکار لجستیک](ADR-004-HANA-LOGISTICS-INDEPENDENT-INTEGRATION.md)، [ADR-044 — جدایی درآمد حنا و لجستیک](ADR-044-SEPARATE-HANA-FIXED-INVOICE-FEE-FROM-LOGISTICS-COURIER-REVENUE.md)

## تصمیم مصوب

**بک‌اند اصلی سامانه حنا با C# و ASP.NET Core بر پایه .NET 10 LTS ساخته شود.** طرح پیشین استفاده از **NestJS/TypeScript برای بک‌اند** در معماری V1.0 و سند V0.1 صرفاً پیشنهاد پیش از این تصمیم بود و با این ADR **در بخش انتخاب فریم‌ورک بک‌اند جایگزین می‌شود**. استفاده از TypeScript در فرانت‌اند وب و موبایل همچنان برقرار است؛ یک‌زبانه‌بودن همه لایه‌ها الزام پروژه نیست.

| بخش | پشته هدف مصوب |
|---|---|
| هسته بک‌اند و REST API | C# / ASP.NET Core / .NET 10 LTS |
| معماری بک‌اند | **Modular Monolith** با مرز دامنه، مالکیت داده، تراکنش و تست روشن؛ چند replica stateless در زمان نیاز |
| پایگاه داده تراکنشی | PostgreSQL با migration نسخه‌دار، پشتیبان‌گیری و بازیابی |
| لایه داده | EF Core برای جریان‌های عمومی و SQL مستقیمِ کنترل‌شده برای query/عملیات خاص پس از اندازه‌گیری یا نیاز سازگاری |
| کارهای پس‌زمینه | .NET Worker Service + outbox + صف پایدار برای تسویه، تطبیق بانک، اعلان و تبادل رویداد |
| کش و هماهنگی موقت | Redis؛ **منبع حقیقت پول، سفارش و اعتبار نیست** |
| وب بازارگاه و پنل‌های فروشنده/سازمان/مدیریت | Next.js + React + TypeScript |
| اپ موبایل | React Native + Expo + TypeScript، فقط برای مصرف‌کننده |
| قرارداد مرزی | REST/HTTPS + OpenAPI نسخه‌دار، idempotency، actor/tenant authorization، event contracts برای اتصال‌های لازم |
| مشاهده‌پذیری و کیفیت | OpenTelemetry، structured logs، audit، CI/CD، تست واحد/یکپارچه/E2E و ابزار مناسب هر لایه |

نام package، نسخه patch، ارائه‌دهنده queue/object storage و ابزارهای جزئی CI/CD طبق نیاز فنی و توان اجرایی در زمان scaffolding ثبت/قفل شوند؛ **این ADR انتخاب سرویس ابری، قرارداد بانکی یا محصول پیام‌رسان خاصی نیست**. هدف نسخه .NET 10 LTS است؛ به‌روزرسانی patch امنیتی در همان خط نسخه با آزمون انجام شود.

## چرا این انتخاب برای حنا

حنا بازارگاه و هم‌زمان سامانه دارای دامنه‌های حساس مالی/سازمانی است: اعتبار حمایتی، کیف پول، دفترکل، بازپرداخت، گزارش اختلاف سفارش و تسویه شبانه. ASP.NET Core و C# برای جداسازی ماژول‌ها، قراردادهای تایپ‌دار، سرویس‌های پس‌زمینه و توسعه نگهداشت‌پذیر انتخاب شده‌اند. **صحت مالی نتیجه طراحی ledger، تراکنش پایگاه داده، idempotency، reconciliation و آزمون است، نه تضمین خودکار فریم‌ورک**. انتخاب .NET به معنی نامناسب‌بودن ذاتی NestJS نیست؛ NestJS فقط پشته منتخب این پروژه نخواهد بود.

## مرزهای غیرقابل تغییر با انتخاب فریم‌ورک

1. معماری شروع **modular monolith** است؛ میکروسرویس‌های مستقل به‌عنوان پیش‌فرض روز اول ایجاد نشوند.
2. لجستیک کسب‌وکار مستقل است و فقط از طریق API/قرارداد تبادل با حنا تعامل دارد (ADR-004)؛ ده درصد درآمد پیک جزو درآمد حنا نیست (ADR-044).
3. مدل واحد سفارش = یک فروشنده، محدودیت‌های اعتبار، نگهداری/استرداد وجه، hold فاکتور و چرخه خودکار **00:00 Asia/Tehran** طبق ADRهای محصول مستقل از فناوری پابرجا هستند.
4. PostgreSQL و ledger تراکنشی مرجع قطعی اطلاعات مالی‌اند؛ Redis یا queue به‌تنهایی برای اثبات یک پرداخت کافی نیستند.
5. قرارداد API باید برای وب Next.js، اپ خریدار React Native و مصرف‌کنندگان سازمانی مستقل از زبان بک‌اند بماند.
6. استقرار، امنیت، تست restore و HA مطابق معماری مصوب بررسی شوند؛ انتخاب .NET به‌خودی‌خود ادعای آماده‌بودن production نیست.

## شیوه شروع در زمان اجازه آغاز توسعه

- ابتدا repository scaffolding برای `apps/api` (ASP.NET Core)، `apps/workers` (.NET Worker)، وب Next.js و اپ React Native/Expo در یک مخزن چندزبانه؛ کتابخانه‌های مشترک C# فقط بین پروژه‌های .NET و **OpenAPI/schema** مبنای قرارداد مشترک میان C# و TypeScript باشد.
- سپس هویت و مجوز، مدل داده و migration PostgreSQL، مرز ماژول‌ها، تست‌های مالی/امنیتی، محیط dev/test و CI تعریف شوند.
- اسکلت مالی با ledger append-only، transaction boundary، idempotency، outbox و reconciliation طراحی شود؛ جزئیات جریان پول صرفاً از ADRهای تجاری موجود بیاید.

## نتیجه ثبت

این ADR **تصمیم فناوری است، نه درخواست فعلی برای کدنویسی**. تا دستور جداگانه مالک محصول هیچ فایل اجرایی یا پروژه scaffold در این مرحله ساخته نمی‌شود.
