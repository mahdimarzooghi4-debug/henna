# ADR-047 — اولویت وب واکنش‌گرای خریدار در ایران و تعویق توسعهٔ بومی iOS

**وضعیت:** تصمیم صریح مالک محصول دربارهٔ اولویت فعلی؛ نه حذف دائمی iOS  
**تاریخ ثبت:** ۲۰۲۶-۰۹-۲۳  
**حوزه:** Buyer Web, Mobile Web, Android Consumer, iOS Native, Delivery Priorities  
**مکمل:** [ADR-045 — پشتهٔ فنی مصوب](ADR-045-HANA-TECHNOLOGY-STACK-ASPNET-CORE-DOTNET-10-LTS.md)، [معماری محصول V1.0](../architecture/HANA-FULL-PRODUCT-NATIONAL-ARCHITECTURE-v1.0.md)

## تصمیم مالک

- در کارهای بعدی، **نسخهٔ وب خریدار با تجربهٔ مناسب گوشی (از جمله مرورگر آیفون) و دسکتاپ** نسبت به توسعهٔ قابلیت جدید در اپ بومی iOS اولویت دارد. مسیری که برای دارندهٔ آیفون از طریق مرورگر قابل استفاده باشد، مستقل از نصب/توزیع اپ iOS پیش می‌رود.
- اپ مصرف‌کنندهٔ **اندروید** در مسیر توسعه باقی می‌ماند. اپ موبایل حنا همچنان فقط برای خریدار است؛ فروشنده، ادمین و سازمان پنل وب دارند.
- توسعهٔ اختصاصی بومی iOS، امضای نسخهٔ انتشار و مسیر توزیع آن **فعلاً در اولویت اجرا نیستند**؛ این تصمیم به‌معنای حذف سورس موجود Expo، لغو دائمی iOS یا وعدهٔ تاریخ انتشار نیست.
- مالک دلیل این انتخاب را موانع عملی دسترسی/توزیع iOS در ایران و ترجیح فعلی برای استفاده از وب‌اپ بیان کرده است. این سند ادعای آمار بازار یا رفتار همهٔ کاربران آیفون ندارد.

## راهنمای اجرا و کیفیت

1. برای گام‌های محصولی قابل‌مشاهده، پیش از افزودن ویژگی اختصاصی iOS، جریان وب خریدار را در عرض‌های موبایل و دسکتاپ، RTL، مرور با لمس، خطا/خالی/لودینگ، جست‌وجو/دسته و لینک‌های عمومی مطابق طرح‌های تأییدشده تکمیل و آزمایش کنید. آزمایش واقعی Safari/iPhone هنگام امکان مفید است؛ سبزشدن Chromium به‌تنهایی اثبات سازگاری Safari نیست.
2. «وب‌اپ» اینجا **اولویت تجربهٔ وب موبایل‌پسند** است؛ نصب‌پذیری PWA، offline، push notification، قابلیت‌های نصب Safari یا پذیرش App Store را بدون قرارداد و آزمون مستقل ادعا نکنید.
3. آزمون‌های فعلی backend، web، mobile، Android و iOS که از قبل در GitHub Actions هستند، به‌صورت خودکار با این تصمیم حذف یا سبز فرض نمی‌شوند. تغییر گیت CI/هزینهٔ شبیه‌ساز یا کنارگذاشتن build بومی نیازمند تصمیم اجرایی جدا و ثبت شواهد است؛ برای رفع شکست موجود iOS نباید به‌صورت نامحدود کار محصولی وب را عقب انداخت.
4. این ADR به طرح‌های مرحلهٔ دوم ثبت‌نام فروشنده در [Frontend 025](../implementation/HANA-FRONTEND-025-DESIGN-PROPOSAL.md) تأیید نمی‌دهد. آن دو طرح همچنان **DRAFT / NOT APPROVED** هستند و قبل از اجرای فرم/API نیازمند تأیید صریح‌اند.
5. هیچ شهر فعال، قیمت، موجودی، فروشندهٔ تأییدشده، پرداخت، پیامک واقعی یا امکان خرید با این تغییر اولویت ایجاد نمی‌شود؛ تجربهٔ وب باید وضعیت واقعی API را نمایش دهد.

## شرط بازنگری

وقتی مالک تصمیم جدیدی دربارهٔ انتشار iOS بگیرد یا نیاز/شواهد معتبر محصولی ایجاب کند، اولویت و شروط انتشار در ADR جدید یا اصلاح صریح همین سند ثبت می‌شوند. تا آن زمان، قابلیت جدید native-only iOS را به‌عنوان «مرحلهٔ بعدی» پیش‌فرض انتخاب نکنید.
