# حنا | Henna

سامانه یکپارچه حنا: بازارگاه وب و اپ خریدار، ثبت‌نام و پنل فروشنده وب، ادمین وب، پرتال سازمان‌ها وب، پرداخت، اعتبار و عملیات.

## مرجع فعلی پروژه

**[سند معماری نسخه کامل حنا و توسعه شهر به شهر — V1.0](docs/architecture/HANA-FULL-PRODUCT-NATIONAL-ARCHITECTURE-v1.0.md)**

اصل محصول: **همه قابلیت‌های مصوب، برای شهر اول به صورت عملیاتی و یکپارچه آماده می‌شوند؛ سپس دامنه جغرافیایی به ترتیب شهرها گسترش می‌یابد.** ساخت داخلی می‌تواند مرحله‌ای باشد اما انتشار عمومیِ ناقص، برنامه محصول نیست. اپ موبایل فقط برای مصرف‌کننده است؛ پنل‌های مدیریتی، فروشنده و سازمان صرفاً وب‌اند.

**تصمیم مصوب پشته فناوری:** [ADR-045 — بک‌اند C# / ASP.NET Core / .NET 10 LTS، وب Next.js و اپ React Native/Expo](docs/adr/ADR-045-HANA-TECHNOLOGY-STACK-ASPNET-CORE-DOTNET-10-LTS.md). بک‌اند Modular Monolith با PostgreSQL، EF Core، Workerهای .NET و Redis فقط برای cache/coordination ساخته خواهد شد. **نسخه NestJS در اسناد قدیمی صرفاً پیشنهاد جایگزین‌شده است.**

[سند اولیه معماری — V0.1 (آرشیو)](docs/architecture/HANA-TECHNICAL-ARCHITECTURE-v0.1.md)

**دامنه لجستیک:** [ADR-046 — بخش لجستیک در پنل ادمین حنا، با سرویس عملیاتی تأمین‌شده از بیرون و صفحه‌های Figma در زمان ساخت همان بخش](docs/adr/ADR-046-ADMIN-LOGISTICS-SECTION-EXTERNAL-SERVICE-FIGMA-DEFERRED.md). اتصال فقط طبق API/قرارداد باشد، نه ساخت سامانه ناوگان داخل هسته حنا.

## شروع پیاده‌سازی

**[Bootstrap 001 — نخستین اسکلت فنی، دستورات راه‌اندازی، وضعیت آزمون و محدودیت‌ها](docs/implementation/HANA-BOOTSTRAP-001.md).**

**[Frontend 001 — پیاده‌سازی فریم‌های ورود و ثبت‌نام فروشگاه از فیگما](docs/implementation/HANA-FRONTEND-001.md).** صفحه‌های اولیه وب در `/auth` و `/seller/register` قرار دارند؛ در این مرحله ارسال OTP و ثبت فروشگاه واقعی هنوز فعال نیست.

**[Frontend 002 — آغاز اپ موبایل مصرف‌کننده با Expo و صفحه ورود از فیگما](docs/implementation/HANA-FRONTEND-002.md).** اپ موبایل فقط برای خریدار/مصرف‌کننده است و ثبت‌نام فروشگاه همچنان صرفاً وب می‌ماند. خروجی Android در CI بررسی می‌شود؛ APK/iOS release هنوز ساخته نشده است.

**[Identity 001 — قرارداد دریافت کد تأیید میان وب/موبایل و بک‌اند](docs/implementation/HANA-IDENTITY-001.md).** پیاده‌سازی فعلی عمداً بدون ارسال پیامک و صدور نشست، خطای 503 شفاف برمی‌گرداند تا پس از انتخاب/اتصال سرویس پیامک، جریان واقعی تکمیل شود.

**[Identity 002 — پایگاه داده Identity و migration نسخه‌دار PostgreSQL](docs/implementation/HANA-IDENTITY-002.md).** جدول حساب و چالش OTP و readiness واقعی DB ساخته شده‌اند؛ داشتن schema هنوز به معنی ارسال کد یا ورود فعال نیست.

**[Identity 003 — هسته رمزنگاری و بررسی یک‌بارمصرف OTP](docs/implementation/HANA-IDENTITY-003.md).** تولید تصادفی امن، HMAC-SHA256 با secret بیرونی، کنترل انقضا و ۵ تلاش ناموفق و مصرف اتمیک در PostgreSQL اضافه شده‌اند؛ ارسال پیامک/ورود عمومی همچنان فعال نشده است.

**[Identity 004 — قرارداد اتصال سرویس پیامک و صدور کنترل‌شده چالش](docs/implementation/HANA-IDENTITY-004.md).** چالش در PostgreSQL با وضعیت ارسال و cooldown ثبت می‌شود؛ فقط تأیید پذیرش از ارائه‌دهنده واقعی آن را قابل بررسی می‌کند. فرستنده پیش‌فرض عمداً غیرفعال است و هنوز پیامک واقعی ارسال نمی‌شود.

اکنون فایل‌های اجرایی پایه در `apps/api`، `apps/workers`، `src` و `apps/web-marketplace` وجود دارند. این‌ها **اسکلت آغاز توسعه‌اند، نه پیاده‌سازی کامل قابلیت‌های سامانه**؛ هنوز تراکنش مالی، اتصال بانک، هویت واقعی، سفارش واقعی، سایر صفحه‌های اپ موبایل، پنل ادمین و رابط لجستیک ساخته نشده‌اند.

V1.0 خط مبنای فنی و معیار پذیرش را مشخص می‌کند؛ سیاست‌های مالی، مجوز، قرارداد تأمین‌کنندگان و تصمیم‌های محصول فصل ۱۴ باید به تصویب صاحبان تصمیم برسند و نباید با فرض مهندسی جایگزین شوند.
